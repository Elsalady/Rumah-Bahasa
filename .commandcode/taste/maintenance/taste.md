- For container deploys on platforms that inject a `PORT` env var (Railway), the nginx config must listen on that port. CORRECTION (fresh failure evidence): envsubst (gettext) substitutes only plain `$PORT`/`${PORT}` — it does NOT understand shell-default syntax, so `listen ${PORT:-80};` is left verbatim and nginx crashes with `invalid port in "${PORT:-80}"`. The working pattern: nginx.conf uses plain `listen $PORT;`, the default is applied in the shell BEFORE envsubst runs (`export PORT=${PORT:-80}`), then `envsubst '$PORT' < default.conf > /tmp/nginx.conf && mv` at container start; also run `php artisan migrate --force --no-interaction` at container start so a fresh PaaS database gets the full schema (including later-added columns like `jenis` that previously caused errors).
