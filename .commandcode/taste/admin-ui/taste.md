The accepted pattern: dark sidebar with brand/logo + title at top, vertical nav items with icons and green active highlight, action buttons (Website/Logout) at the bottom, main content to the right of the sidebar; collapsing to a horizontal scrollable bar on mobile. - Use detail/show pages (click → detail view) for reviewing user documents and data rather than displaying everything inline in a table row. Confidence: 0.75
- Keep admin pages for similar data types (e.g., Data Member and Pendaftar Program) visually and functionally consistent — same layout style, same table features (export CSV), same header structure. Confidence: 0.75

- The admin panel should follow a dark monochrome terminal / Filament-style theme (including a left-side Filament-style sidebar — see the sidebar learning above) — black/gray/white palette (e.g., GitHub-dark-like `#0d1117` backgrounds, `#21262d` borders), and at most a single terminal-style accent color (e.g., green `#3fb950`) — the user explicitly requested "hitam abu putih seperti terminal command prompt ... simple native tidak warna warni seperti template ai". The admin look should feel like a native dev tool, NOT like a colorful AI-generated template. The terminal vibe must NOT make all text stiff: the user explicitly said the writing should not be too stiff ("tulisannya jangan terlalu kaku"), so body/content text (nav, stat numbers, labels, tables, buttons, forms) should use a modern readable sans-serif (Segoe UI / system-ui), with monospace (Cascadia/Consolas) reserved only for the terminal-style header/title accent (e.g., "> Panel Admin" with the green `>` prompt). Confidence: 0.9
- In the admin UI, status badges/indicators (approved/pending/rejected/confirmed, program jenis/mode, etc.) should be monochrome gray pills, not color-coded (green/amber/red) — colorful status pills were explicitly stripped as part of the "tidak warna warni" requirement. Keep a single green accent for "active"/primary-action states only. Confidence: 0.8
- Admin panels should be stripped of decorative flourishes (gradient orbs, floating/ornamental animations, heavy shadows, colorful inline styles, gradient card borders) for a flat, clean, "native" look — the "simple native, not AI-template" aesthetic applies to admin tools, in contrast to the public marketing pages where the user does want premium gradients/animations. Confidence: 0.78
- In-page sub-section selectors within an admin menu (e.g., Konten → "Edit Konten Profil" vs "Edit Berita"; Member → "Pendaftar Member" vs "Pendaftar Program") must be prominent, obviously-clickable buttons — solid filled backgrounds with icons, large padding, and a clear active state (solid green active vs dark-gray inactive, with title + subtitle) — never subtle underline tabs or plain-text links. The user explicitly complained the member tabs "ga mencolok, hamper mirip seperti text biasa" and that they made it confusing to find pendaftar member vs pendaftar program; the accepted pattern is the big switch/card buttons used on the Konten page (solid green active state, icon + title + subtitle) and the solid segmented buttons on the Member page.
